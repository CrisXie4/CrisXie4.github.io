# 服务器自托管部署指南

> ## ✅ 当前部署状态（2026-08-31，已由自动化完成）
> - 服务器：38.76.168.127（Ubuntu 24.04，与 qqbot 同机）
> - 站点目录：`/var/www/blog/src`（仓库克隆）→ 构建产物 `/var/www/blog/dist`，Node 20 自带于 `/var/www/blog/node20`
> - nginx：`/www/server/panel/vhost/nginx/blog.crisxie.top.conf`，**80 端口、Host=blog.crisxie.top**
> - 自动更新：`/etc/cron.d/blog-update` 每分钟执行 `/var/www/blog/update.sh`（拉取→按需构建→同步 dist），日志 `/var/www/blog/update.log`
> - 访问方式：需要在域名 DNS 处添加 A 记录 **blog → 38.76.168.127**，之后通过 `http://blog.crisxie.top` 访问
> - 注意：服务器上 `/etc/crontab`、`/etc/systemd/system`、`/etc/cron.d` 带不可变锁（服务商加固），cron 用「临时解锁→写入→重新上锁」方式部署；宝塔原 `node_server.conf`（8081）因与 python 进程端口冲突已备份停用
> - 冲突 vhost 备份：`/www/server/panel/vhost/nginx/node_server.conf.bak-20260831`

> 现状：网站托管在 GitHub Pages（免费、自动 HTTPS、推送即上线）。
> **如果服务器只是为了"放网站"，其实不需要服务器。** 服务器的价值在于：国内访问加速、完全自主可控、跑后台认证服务等。
> 想自托管时，按下面步骤操作。两边可以并存（Pages 一个地址、服务器一个地址）。

## 架构

```
浏览器 /admin/ 后台（GitHub 令牌登录）
        │ 写文章 / 传图片，直接提交到 GitHub 仓库
        ▼
GitHub 仓库（文章、图片、全部源码）
        │ push 事件触发
        ▼
GitHub Actions 自动构建出 public/ 静态文件
        │ 部署
        ▼
GitHub Pages（现状）          服务器 nginx（自托管，二选一或并存）
```

## 一、服务器基础环境（以 Ubuntu/Debian 为例）

```bash
# Node 20 + git + nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs git nginx
```

## 二、拉取并构建博客

```bash
sudo mkdir -p /var/www/blog && sudo chown $USER /var/www/blog
git clone https://github.com/CrisXie4/CrisXie4.github.io.git /var/www/blog/src
cd /var/www/blog/src
npm ci
npx hexo generate            # 产物在 public/
sudo mkdir -p /var/www/blog/dist
sudo cp -r public/* /var/www/blog/dist/
```

## 三、nginx 配置

`/etc/nginx/sites-available/blog`：

```nginx
server {
    listen 80;
    server_name your-domain.com;      # 换成你的域名或服务器 IP

    root /var/www/blog/dist;
    index index.html;

    location / {
        try_files $uri $uri/ $uri/index.html =404;
    }

    gzip on;
    gzip_types text/css application/javascript image/svg+xml application/json;
}
```

```bash
sudo ln -s /etc/nginx/sites-available/blog /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

HTTPS（有域名时）：`sudo apt install certbot python3-certbot-nginx && sudo certbot --nginx`

## 四、更新自动化（二选一）

**方案 A：定时拉取（最简单，1 分钟延迟可接受）**

```bash
# 服务器上放一个脚本 /var/www/blog/update.sh
cd /var/www/blog/src && git pull -q && npx hexo clean -q && npx hexo generate -q && sudo rsync -a --delete public/ /var/www/blog/dist/
```

`crontab -e` 加一行（每分钟检查一次）：

```
* * * * * cd /var/www/blog/src && git fetch -q && [ "$(git rev-parse HEAD)" != "$(git rev-parse origin/main)" ] && bash /var/www/blog/update.sh
```

**方案 B：GitHub Actions 构建后推到服务器**（服务器不装 Node）

在仓库 Settings → Secrets 添加 `SERVER_HOST`、`SERVER_USER`、`SERVER_SSH_KEY`，
然后在 `.github/workflows/pages.yml` 的 deploy job 后追加一个 rsync/scp 步骤。
